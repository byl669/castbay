# 方案一：桌面端界面优化（待确认，确认前不动代码）

## 1. 现状的问题

1. **所有东西挤在一页**：接收端列表、屏幕/窗口、画质、编码器、声音、开机自启全在一个竖向页面里，
   用户每次投屏前都要先扫一遍一堆选项，而"选设备 → 开始"才是 95% 的使用场景。
2. **没有"设置"这个概念**：声音开关在主页，开机自启在页脚，画质编码器在中间，找不到统一入口。
3. **设置存在网页的 localStorage 里**：托盘、开机自启启动时 Rust 一侧读不到，也无法被命令行共享。
4. **投屏中界面像调试面板**：解码 ms、丢帧、码率这些数字占了主视觉，普通用户只关心"在投、投到哪、怎么停"。
5. **不能管理已配对的接收端**：只有出错时才能"忘记"；平时看不到配对了谁。
6. **缺少视觉层次**：没有图标、没有空状态设计、浅色/深色只是简单反色，窗口尺寸和留白也没经过设计。

## 2. 目标

- 主页只回答三件事：**投给谁、投什么、开始**。其余选项都进设置页。
- 投屏中页面以"状态 + 停止"为主，技术数字收进"详细信息"。
- 设置页分组清楚，改了立刻生效或下次投屏生效（页面里写明）。
- 视觉上参照主流投屏/远程类应用（Chromecast 桌面端、AirDroid、Parsec、Moonlight 一类）：
  顶栏 + 设备卡片 + 底部主操作按钮；设置用二级页面（返回箭头），分组列表（行 + 开关/选择）。

## 3. 信息架构（示意图见对话中的三屏）

### 3.1 主页
- 顶栏：应用名 + 右侧**设置**图标。
- **接收端卡片列表**：名称、副标题（"已配对 · 局域网" / "首次需配对码" / "需要密码"）、锁图标；
  选中态用强调色边框；右上角刷新图标；空状态有插画式图标 + 两行说明（开启"电脑投屏"、允许防火墙）+ "重新查找"。
- **投什么**：分段控件（整个屏幕 / 某个窗口）+ 下拉选择（多显示器时显示每个屏幕的分辨率；窗口列表带刷新）。
- 主按钮 **开始投屏**（未选接收端时可点，点后提示"先选一个接收端"，不使用灰色禁用）。
- 按钮下一行小字摘要："均衡画质 · 带声音 · 更改"，"更改"直接跳到设置页对应位置。
- 首次运行的引导卡片仍显示在顶部，可关闭。
- 有新版本时顶部显示一条可关闭的提示条。

### 3.2 投屏中
- 大状态区：图标 + "正在投屏" + 接收端名称 + "1728×1080 · 30 帧 · 带声音"。
- 一个**停止投屏**按钮（危险色，唯一主操作）。
- "详细信息"折叠区（默认收起）：接收端解码、帧率、丢帧、码率。
- 条件提示条：配对码输入（需要时出现，输入框放大、自动聚焦）、重连中、电脑已锁屏。
- 小字："关闭窗口，投屏继续在托盘运行"。

### 3.3 设置页（二级页面，左上角返回）
- **画质**：低码率 / 均衡 / 高帧率 三选一，下方一行说明（"30 帧 · 8 Mbit/s，大多数场景够用"）。
- **同时传声音**：开关。
- **编码器**：自动 / AMD / NVIDIA / CPU（说明"自动会按 AMD → NVIDIA → CPU 依次尝试"）。
- **通用**：开机自动启动（开关）；语言（跟随系统 / 中文 / English）。
- **已配对的接收端**：二级列表，每行显示名称、最后连接时间、"忘记"。
- **关于**：版本号 + 检查更新（状态：已是最新 / 有新版本→打开发布页）；打开日志文件夹；开源许可证（GPL-3.0）与源码链接。

## 4. 视觉与交互规范

- 沿用现有的浅色/深色自适应（跟随系统），定义统一的颜色/间距/圆角变量：
  间距 4/8/12/16/24；圆角 8（控件）/12（卡片）；字号 12/13/14/16/20；字重只用 400 和 500。
- 图标用 Tabler 的描边图标（MIT 许可），**内联 SVG** 嵌入，不引外部资源，不增加打包体积（约 20 个图标）。
- 状态色只用语义：强调色（选中/主按钮）、成功（投屏中）、危险（停止）、警告（锁屏/重连）。
- 窗口默认 540×660，最小 460×560；内容最大宽度居中。
- 可访问性：全部可键盘操作（Tab/Enter/空格/Esc 返回），焦点环可见，列表和开关有 ARIA 角色，对比度满足 WCAG AA。
- 文案遵守项目的用词规范（句子式大小写、不用"请"、不加感叹号、动词开头）。

## 5. 数据与后端改动

| 项 | 现在 | 改成 |
| --- | --- | --- |
| 设置存放 | 网页 localStorage | Rust 侧 `settings.json`（应用数据目录）：quality、send_audio、encoder、language、上次选的接收端/来源 |
| 命令 | `start_cast(全部参数)` | `start_cast(接收端, 来源)`，其余由 Rust 读设置；新增 `get_settings` / `set_settings` |
| 迁移 | — | 首次启动把 localStorage 的旧值读一次写进 settings.json |
| 已配对接收端 | `receivers.json` 只存 id→密钥指纹 | 升级为 id→{指纹, 名称, 最后连接时间}，**兼容读旧格式**；新增 `list_paired` / `forget_receiver` |
| 语言 | 随系统 | 增加手动选择；托盘菜单文字同步 |

## 6. 不做（本轮范围外）

- 手动切换浅色/深色（先只跟随系统）；多窗口；自定义快捷键；动画（只保留必要的过渡）。
- 不改引擎、协议、安装包。

## 7. 测试

- 用 DevTools 驱动真实窗口跑完整流程：发现 → 选择 → 配对码 → 投屏 → 详情展开 → 停止 → 设置各项改动并重启后仍在 → 忘记接收端；
  每一屏截图（中/英 × 浅/深 × 最小窗口/默认窗口）并逐张检查。
- 键盘全流程、屏幕阅读器标签（用浏览器无障碍树检查）。
- 回归：Sony 上完整投屏（含声音、重连、托盘关闭继续、开机自启）。
- 设置迁移：旧版本升级后配对记录和选择不丢。

## 8. 拆分与顺序（每步独立 PR，各自验证）

1. 设置后端：`settings.json`、命令、localStorage 迁移、配对记录格式升级（无界面变化）。
2. 新的界面框架 + 主页 + 投屏中页（样式规范、图标、空状态）。
3. 设置页（画质/声音/编码器/通用/语言）。
4. 已配对接收端管理 + 关于页（版本、检查更新、日志、许可证）。
5. 收尾：多语言文案校对、键盘/无障碍、截图自查、用户说明更新。
